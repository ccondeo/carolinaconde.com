# CLAUDE.md

Guidance for AI assistants working in this repository.

## What this is

The personal portfolio site for **Carolina Conde** (translator, builder,
"channeler"), served at **carolinaconde.com**. It is a **static website hosted
on GitHub Pages** — there is no framework, no build step, no package manager,
and no server-side code. Every page is a single, self-contained `.html` file
with all CSS and JavaScript inlined.

## Repository structure

```
.
├── CNAME                      # GitHub Pages custom domain → carolinaconde.com
├── README.md                  # One-liner
├── index.html                 # Homepage: hero + filterable "Selected work" grid
└── work/                      # One self-contained subpage per project
    ├── sierpinski/index.html      # Interactive fractal exhibition (creative)
    ├── glossary/index.html        # Bilingual ballroom/drag glossary (translation)
    ├── emerging-careers/index.html# AI/work careers intelligence ref (technology)
    ├── invoice-generator/index.html# Invoicing tool for translators (tools)
    └── band-caliper/index.html    # Color-band measurement tool (tools)
```

Each project lives in its own directory as `index.html` so it gets a clean URL
(e.g. `carolinaconde.com/work/sierpinski/`).

## Deployment

- Hosting is **GitHub Pages**, configured for the custom domain in `CNAME`.
- **Pushing to the default branch publishes the site** — there is no CI/build
  pipeline (`.github/` does not exist). What is committed is what goes live.
- To preview locally, open any `index.html` directly in a browser, or serve the
  root with a static server (e.g. `python3 -m http.server`).

## The homepage work grid (most common edit)

The project grid on `index.html` is **data-driven**. To add, remove, or change a
project card, edit the `works` array inside the `<script>` block near the bottom
of `index.html` — do **not** hand-write card HTML; it is generated by `render()`.

Each entry has this shape:

```js
{
  title: 'BandCaliper',
  desc:  'Measures color band widths from any image. ...',
  cat:   'tools',        // translation | technology | tools | creative | education
  lang:  'EN',           // free text, e.g. 'EN' or 'EN / ES'
  status:'soon',         // live | preview | soon
  link:  'work/band-caliper/'  // relative path, external URL, or null
}
```

Behavior driven by these fields:
- **`cat`** colors the category chip and must match one of the five filter
  buttons (`data-f` values) and a `--c-*` CSS variable / `.cat-*` class.
- **`status`** controls the label and whether the card is a clickable link:
  only `status: 'live'` renders an `<a>` with an arrow; `preview` and `soon`
  render a non-clickable `<div>`. A `live` card **must** have a non-null `link`.
- **`link`** starting with `http` opens in a new tab (`target="_blank"`).

When you add a new category, you must update all of: the `works` entry, a
`data-f` filter `<button>`, a `--c-<name>` variable in `:root`, and a
`.cat-<name>` rule.

## Conventions

- **Self-contained pages.** Keep each page's CSS in a `<style>` block and JS in
  a `<script>` block within the same file. No shared/external CSS or JS files,
  no bundler. Don't introduce a build step or dependencies without being asked.
- **Each page styles itself independently.** There is no global design system —
  every page defines its own `:root` CSS variables, fonts, and palette. The
  homepage and each `work/*` page have different aesthetics on purpose. Match the
  conventions of the specific file you are editing; do not unify them.
- **Fonts** load from Google Fonts via `<link>` or `@import`. The homepage uses
  Fraunces (serif), DM Sans (sans), DM Mono (mono).
- **Dark, editorial aesthetic** on the homepage: near-black background, warm
  off-white text, a single accent (`--accent: #E8825A`). Use the existing CSS
  variables rather than hard-coding colors when editing a page that defines them.
- **Responsive** via plain CSS media queries (homepage breakpoints: 860px,
  520px). Preserve responsive behavior when changing layout.
- **Vanilla everything.** Plain HTML/CSS/JS, no libraries. The homepage uses an
  `IntersectionObserver` for fade-in (`.fi` → `.vis`).
- **Indentation is inconsistent across files** (the homepage `<style>` is dense
  with little indentation; `work/*` pages use 2-space). Follow whatever the file
  you are editing already does.

## Working in this repo

- Make changes directly to the relevant `.html` file; verify by opening it in a
  browser.
- Commit messages in history are short and descriptive (e.g. "Update status of
  BandCaliper to 'soon'", "Revise hero bio and meta information in index.html").
  Match that style.
- **Only commit/push when asked.** Pushing to the live branch publishes the
  site. Develop on the branch you were assigned; never push to another branch
  without explicit permission.
- **Do not create a pull request unless explicitly asked.**
- Contact / footer email used across the site: `translator@carolinaconde.com`.
